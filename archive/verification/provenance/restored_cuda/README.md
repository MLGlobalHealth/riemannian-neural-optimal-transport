# Controlled historical software candidate on NVIDIA

These are fresh, separately labeled reproduction trials. They use the provenance-based JAX 0.4.35 / Flax 0.8.4 / Optax 0.2.3 candidate on NVIDIA RTX 6000 Ada hardware. Python is 3.11.15; the historical notebook metadata records 3.10.19. The official CUDA extra selects jaxlib 0.4.34 plus CUDA plugin/PJRT 0.4.35, whereas the historical AMD setup note records jaxlib 0.4.35 with ROCm plugins. This is therefore the **closest official CUDA packaging combination**, not the original AMD environment.

The original attempt to pin jaxlib 0.4.35 together with the CUDA extra was rejected by pip before installation. `resolution.log` and `preparation_status.json` preserve that initial failure. The supported packaging adjustment was selected before any experimental result. `supported_preparation_status.json`, `supported_install_report.json`, and `requirements_resolved.txt` describe the installed candidate. `pip_check.log` records consistent declared dependencies. No package or experiment source was patched. JAX's supported `CUDA_ROOT` variable points to the actual installed toolkit directory, bypassing its older automatic discovery code; `before_cuda_root_cpu_native_builds.json` preserves the original discovery failure.

Both native historical builders passed bounded CPU initialization checks before GPU training. `cpu_native_builds.json` records package versions, x64 enabled, the native threefry partitionable flag set to false, and parameter/landmark/sample fingerprints. `cpu_zip_configured.json` provides corresponding evidence for the ZIP with the pre-existing historical settings. These build-only checks did not train models.

The historical source is the exact 24-file snapshot of `dbf533d86b7b259b42282f0d55c95915c181add6`; `source_verified.json` records every file hash. The separately authorized ZIP comparison uses the exact 22 archive files and only the previously documented `historical_settings.json` overrides plus x64 enabled; `zip_source_verified.json` records archive verification. `launches.json` and `zip_launch.json` preserve complete commands and environment path/device settings. GPU availability was checked twice before each launch; foreign processes were left untouched.

The configured ZIP S2 random trial completed with KL 0.03931675014307971 and ESS ratio 0.9513898505374285. Its mean KL is identical to the historical-source candidate; raw batch KL differences are at most 1.39e-17. `historical_vs_zip_same_seed_comparison.json` preserves all compared values and input record hashes. The historical S2 random reference for this seed is KL 0.0394 and ESS ratio 0.951, from committed `table_random.log`. `historical_ours_same_seed_comparison.json` records that 974 of its 1,000 printed training losses match at four decimals. The historical RCPM references for this seed differ slightly between stored logs: KL 0.0067 / ESS 0.996 in `table_fps.log`, and KL 0.0070 / ESS 0.996 in `table_random.log`.

Stored logs are historical references, not newly executed results. These single-seed trials do not reproduce a five-seed paper mean or its across-seed uncertainty. Per-run result JSON files contain the unrounded metrics and all five evaluation batches; their batch standard errors must not be mistaken for across-seed uncertainty. Checkpoint hashes were verified after downloading.

A full prescribed five-seed ZIP cohort was subsequently authorized. `restored_zip_cohort_manifest.json` fixes all 19 new nvidia7 jobs and counts the completed random-seed 12345 pilot unchanged: nine further S2 RNOT random/FPS runs and ten S2/T2 RCPM runs. These run on GPUs 2/4 with sequential capacity checks. RNOT uses label `zip_historical_settings_cuda_jax435`; RCPM uses `zip_x64_cuda_jax435`, x64 enabled, and no configuration overrides. The pilot table above contains only the initial same-seed checks. The later complete-cohort findings are recorded separately in the main report and per-seed comparison.
