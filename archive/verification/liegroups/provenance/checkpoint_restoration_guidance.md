# Native Lie-group checkpoint restoration requirements

Read-only guidance for the separate evaluator; no training, evaluation, parameter modification, or experiment-source change was performed by this reviewer. All four completed source records and local checkpoint file hashes were checked; evidence is in `checkpoint_restoration_inputs.json`.

1. Verify the completed training record's source/helper/wrapper/native-runner hashes, checkpoint SHA256, recorded pinned environment, native seed/configuration, and exact five evaluation subkeys. The Lie-group schedule starts from seed 12345 without the old table evaluator's +1000 offset. The four real records share their five saved uint32[2] subkeys. Replay them verbatim; never use the retained checkpoint training key for evaluation.
2. Load the matching unchanged recovered native module and call its builder without overrides. SO3 RNOT returns `cfg`; SE3 returns `model_cfg`, `solver_cfg`, and `training_cfg`. Reuse the wrapper's `native_configuration` and `density_configuration` plus its exact geometry schema to compare reconstructed settings against the saved result. SE3 target location metadata reflects its post-constructor normalization, not merely the literal constant. Preserve SE3's native 100 inner steps / 500 minimum; no historical S2/T2 override applies.
3. RNOT: deserialize the saved top-level `params` and `landmarks`, retaining every array dtype, shape, and byte. Cross-check top-level params with `payload['state']['params']`. Build a new `GromovDistanceEmbedding` from checkpoint landmarks and the native manifold, clone the native psi with that embedding, replace `exp['psi']`, and use `exp['state'].replace(params=restored_params)`. Create a new `ArgminSolver(manifold=..., psi_module=new_psi, **dataclasses.asdict(native_solver_cfg))` so its JIT closures reference the checkpoint embedding. Never mutate the frozen Flax module or reuse an already-built solver with a substituted field.
4. Native RNOT evaluators read `state.params`, `psi`, `solver`, `base`, `target`, and `manifold`. They do not use trainer/loss/apply_fn references or optimizer state; those need not be reconstructed for evaluation. SO3 calls `compute_kl_ours`; SE3 calls `evaluate`, which already returns its native `mean_residual` along with KL/ESS/ratio. Do not add a second diagnostic solver call.
5. RCPM gamma1: call `build_rcpm_experiment(gamma=1.0, seed=12345)`, guard the constructed flow/configuration/data/geometry, and assign the complete saved `payload['params']` variables dictionary to `exp['params']`. This dictionary includes its own top-level `params` collection. Passing only that collection would have the wrong Flax apply structure. `SequentialFlow` is unbound, and `ExpMapFlow` constructs its parameter-dependent closures inside apply; there is no separate persistent parameter capture to replace. Call unchanged `compute_kl_rcpm` with the saved subkeys.
6. Do not infer all parameters are float64 from x64 being enabled: both real RNOT models have float32 parameters and both RCPM models mix float32 and float64. Fingerprint restored arrays against deserialized arrays; also verify parameter count and landmark shape/count before evaluating. Fresh random builder parameters/landmarks may differ across devices and are discarded in favor of the fixed checkpoint.
7. Label each output evaluation-only and never an independent training replicate. Retain original/result/checkpoint/evaluator hashes, actual host/runtime settings, raw metrics, original metrics and differences, and failures. Sampling occurs through the same native density functions on each host, so identical saved keys do not by themselves prove byte-identical sampled arrays.
